# Learned rules

Tiebreakers the user has resolved by hand. `/work-case` Step 3 reads this file
**before** its own built-in rules, so anything written here wins.

Every entry here started life as an interruption. The whole point is that it only
costs a question once.

## Format

```
### <short situation key>
**When:** the condition that makes this rule apply
**Then:** what to do
**Learned:** YYYY-MM-DD, from <case number>
```

## How to add one

Append after any Step 6 stop, once the user has answered. Write the *general* rule
their answer implies, not the specific case — "when a district folder has both a
`-Tri` and a bare variant and the case says nothing about terms, use the bare one"
beats "for SODD1-JAM use the bare one".

If a new rule contradicts an older one, replace the old entry rather than stacking
a second one next to it. Two rules that disagree are worse than none — you end up
asking anyway.
